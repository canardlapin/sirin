# Bounded tessellation, texture atlases and ordered GPU batches

Date: 2026-10-28. Parent: `bd-01M5ZV4M9SB36V3BJACKJXDJFW`.
Tranche: `bd-01M61WNMKA96EVATY9K8RTT1TF`.

This is a standalone direct-wgpu implementation slice. It advances the graphics
nucleus without claiming a full G-1/G-2 exit, browser parity or mounted-host
acceptance. The public drawing model and kernel policies are unchanged. ThorVG
remains unadopted under the earlier color-composition finding.

## Frozen inputs and implementation

The [original contract](batch-20261028/contract.json) was written before coding;
its SHA-256 is `9036581d266e355cb7abb30f0a2cadd582fde2bd62e10a386d162c64e0e46093`.
Its scene counts, four scales, two-byte pixel tolerance, 0.0001-device-unit tie
rule, timing limits and CPU/GPU cache/payload bounds were not relaxed.
[Input hashes](batch-20261028/inputs.json) pin the measured source and artifacts.
The workspace remains an active shared checkout, based on `ae1817f`; this is not
a frozen release candidate or a clean-worktree receipt. The existing reference
compiler/C shim and desktop/host reservations were respected.

`BatchCompiler` intersects nonzero/evenodd fills with prepared path clips and the
viewport. It cancels exact opposite directed edges, generates crossing events,
then decomposes the winding intersection into nonoverlapping triangles. Connected
filled intervals merge across internal winding-count changes. Adjacent scanbeam
strips also merge when their two boundary edges are unchanged, avoiding redundant
triangles at internal crossing events. Translation-
normalized meshes reuse CPU preparation and fixed GPU spans across placements,
paints and independent recordings. Per-program index/paint records preserve
painter order; consecutive draws batch until a layer boundary. Isolated opacity
uses intermediate attachments and ordered source-over composition.

The shared stroke preparer now also cancels exact opposite edges and extracts
closed walks from the balanced boundary graph before flattening. The retained
winding function is unchanged, including self-overlaps and holes. This removes
internal ribbon diagonals/interfaces from point storage and permits the frozen
100-curve corpus under the existing default 262,144-point preparation limit.
Per-stroke work, curve precision, cusp refusal and point/depth limits remain.

Glyph coverage uses 1024x1024 R8Unorm atlas storage with 64x64 fixed cells.
Exact font bytes/face/size/glyph/metrics/versions/requested density key the CPU
raster cache; placement uses the actual quantized raster density. Glyph paint is
independent of masks, and rendering never reshapes. Images use 1024x1024
RGBA32Float texture storage with 256x256 cells, decoded to linear-premultiplied
pixels before manual nearest/bilinear fetches. Fetches clamp to the source image,
so adjacent cells do not bleed; fractional crops retain neighboring source texels
as specified by the existing sampling contract.

Atlas cells and mesh spans remain stable while pinned by retained programs.
Only idle entries evict, including under forced pressure. Failed retention rolls
back acquired references; it may leave valid idle cache entries. Program/parent
close synchronously retires GPU children and clears retained CPU dependencies.
New device sessions require new preparation. Owners and compilers are confined
to their creating Scala thread. All native callbacks write native-owned state;
blocking externs are annotated and inventoried in VISION §5.4.

## Precision and preserved failures

The initial half-float/fixed-function raster path failed the frozen oracle at
1.5x. A faint glyph produced zero RGB where the reference retained `(155,214,0)`
with quantized zero alpha; a curve/layer pixel differed by five bytes.
[The diagnostic run](batch-20261028/test-6.log) preserves both failures.
[The float32-only run](batch-20261028/test-7-float32.log) fixes the glyph but
preserves the curve discrepancy, separating precision from edge coverage.

The corrected path explicitly requires actual `Float32Blendable` capability.
Padded conservative triangle bounds admit fragments; canonical half-open f32
triangle predicates determine coverage rather than hardware subpixel edge
snapping. Four rows of the original 4x4 grid stream through 4x-width/1x-height
RGBA32Float attachments and accumulate before the final straight-sRGB RGBA8
resolve. This retains all 16 sample positions under the original 192 MiB payload
bound. There is no half-float fallback. See
[the implementation revision](batch-20261028/implementation-revision.json).

The earlier tessellator exhausted its triangle limit by emitting regions at
internal edges; exact edge cancellation and merged filled intervals address that
without raising the limit. The first corpus run hit the source preparation point
limit at 1.5x; exact stroke-boundary compaction addresses it without raising that
limit. Compile diagnostics, the interrupted allocation-heavy comparator, the
shader conversion error and these admission failures remain in the run logs.
No test was stubbed, skipped or weakened to admit the result.

## Verification and bounded corpus

The verification helper runs the existing reference interpreter on 16x16 tiles,
with exact fill-bounds rejection and translated paths/clips/paint anchors.
Layer commands and all glyph/image draws remain in their original order.
This preserves its original per-sample work limit. A separate four-scale test
compares tiled output with whole-image reference output before using it for the
larger corpus. Every non-tie pixel and all RGBA channels are compared, including
RGB at quantized zero alpha. The tie mask is derived independently from source
and clip boundaries using the frozen distance rule; no blanket image threshold
is used. An independent winding/triangle-union test checks holes, crossings,
multiple windings and overlapping ribbons. Existing analytic curve/dash/stroke
checks and a new self-overlap segment-distance oracle remain active.

The standalone `BatchBenchmark` records 512 ordered translucent marks, 100 cubic
strokes, 16 labels in Latin/Arabic/Hebrew/Devanagari, a 64x64 RGBA image, gradients,
clips and two isolated groups at 320x180 logical pixels. Exact font files are
pinned; every shaped benchmark glyph is checked for missing-glyph ID zero.
At each scale it measures 10 cold preparations, 120 warmups and 600 completed
submissions, then readback, overlay and 32 immutable image replacements. Font
resolution/shaping and initial recording construction precede the cold clock.
Cold timing includes drawing preparation and mesh/mask/image compilation.
GPU owner/pipeline initialization also precedes timed preparations.

`submit()` includes command encoding, all sample rows/layers, resolve, queue
submission and synchronous completion; it excludes readback. It is CPU wall time,
not GPU timestamps or display/input latency. Readback timing additionally includes
mapped staging and returned snapshot copies. Measurements use the pinned Apple
M2 Pro, wgpu-native 29.0.1.1, Scala 3.7.4, Scala Native 0.5.12 debug/Immix; native
multithreading is detected for tests and disabled by detection in the standalone
benchmark. No shipping optimization or cross-backend throughput claim is made.

## Resource bounds and remaining gates

CPU caches cap mesh payload at 8 MiB and decoded/raster payload at 4 MiB, each
with at most 256 entries. These exclude source snapshots/fonts, caller-held
compiled dependencies, temporary preparation/marshalling and object overhead.
Compiled texture inventories also cap at 16 images/256 masks. Source images
larger than 256x256 and glyph masks larger than 64x64 explicitly refuse this path.
GPU defaults allocate an 8 MiB mesh arena, a 1 MiB R8 atlas and a 16 MiB RGBA
atlas. All program buffers, output/intermediate textures, accumulation/phase
buffers and those fixed capacities count against 192 MiB. At most 16 programs,
two layer levels and a 640x360 device target are admitted. Geometry admits at
most 4,096 input edges per tessellation, 16 million intersection pairs and
262,144 compiled/expanded triangles. Driver/pipeline/bind-group overhead and
transient command/staging allocations are excluded from payload counters.

Copies remain explicit: source snapshot import, CPU image decode and glyph mask
copy, Scala/native marshalling, GPU geometry/texture/program upload, then optional
mapped readback, native output, Scala array and immutable snapshot copies.
Unchanged retained replay uploads no source or command data and rasterizes no
new masks. Source replacement is a new immutable snapshot; old pinned programs
retain their original pixels. No finalizer or later frame is needed for disposal.

The fixed-cell atlas is a bounded real texture implementation, not production
atlas packing or a complete host cache. Larger targets/corpus sizes, broader
cusp/paint/effect coverage, full G-1 pinned browser references, GPU timestamps,
allocation/driver-memory profiling, input-to-display latency, human visual
acceptance, mounted-host integration and the explicit G-2 backend exit decision
remain open. The 1280x720 general graphics protocol is not certified by this
320x180 implementation corpus.
