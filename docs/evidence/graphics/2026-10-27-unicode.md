The original run passed 6/8 suite tests; grapheme/line tests stopped at those first

`/private/tmp/sirin-unicode-original-capi-failure-20261027.log`.
The pinned upstream segmenter tests select `new()` for Unicode 17 graphemes,
the legacy constructor for Unicode 15.1 lines, and `new_neo*` for Unicode 18.
The generated C API exposes only the older constructors. Compiled-data version
alone therefore did not establish algorithm conformance.

`native/unicode-probe/src/lib.rs` now supplies a small pointer-only C ABI that

`LineSegmenter::new_neo_for_non_complex_scripts`. It uses the pinned `unstable`
feature; upgrading requires rebuilding and rerunning all reference tests. It
does not implement or patch Unicode rules. Word segmentation and bidi continue
through ICU4X's generated C API. All pieces are in the same Rust static library.
The tests and expected reference records were not weakened or excluded.

## Ownership, semantics and verification

Standalone `UnicodeAnalysis` retains validated `TextSource`, typed UTF-8/UTF-16
and grapheme mappings, word/line boundaries and categories, raw byte-indexed bidi
levels and paragraph ranges/direction classes. The version label is release-pin
metadata, not a runtime version query. This is analysis, not positioned text.

`NativeUnicode` has explicit creating-Scala-thread ownership and close, with no
finalizer, Scala callback or foreign-created thread. Input length is rejected
before encoding when code units exceed budget; valid encoded input is checked
against a configurable ≤1 MiB byte budget. Native allocation/counts are bounded.
The C shim contains every Diplomat slice/option/result struct. Input bytes live
in native storage until all native iterators/bidi objects are destroyed. Results
are copied into owned Scala values before native output retirement. Analysis
survives engine closure. Native analysis/allocation/destruction calls are
`@blocking`, listed in VISION §5.4; count/pointer accessors are bounded plain
externs. The wrong-thread test uses a Scala-created thread and does not replace
the existing P0.6/P0.7 gates.

Reference fixtures are unmodified official Unicode 18.0.0 data with license,
[source note](../../../probes/unicode/src/test/resources/unicode/SOURCES.md) and
SHA256SUMS, verified before test execution. Exact UTF-8 boundaries pass for every
record in the following files:

| Corpus | Passing records |
|---|---:|
| GraphemeBreakTest | 853 |
| WordBreakTest | 1,944 |
| LineBreakTest | 19,346 |

Line tests add structural zero because ICU iterators include it while LB2 marks
the start as unavailable for wrapping; internal/end expectations are unchanged.
Word/line analysis uses default Unicode rules, no dictionary/locale tailoring.
Eight native suite tests also cover the first 16 BidiCharacterTest examples,
emoji ZWJ/modifiers/flags, combining sequences, CRLF, word categories, mixed/RTL
paragraph ranges, empty input, copied-result survival, closure, invalid
surrogates, byte budgets and wrong-thread rejection. The other 91,691 bidi
records are not asserted: raw levels precede line-dependent L1/L2. No full UAX #9
layout or complex-script dictionary quality claim is made.
