## Architecture and API decision

The pure JVM/Native `textUI` cross-project (`sirin-text-ui`, `text-ui/`) depends
on core and graphics. Neither foundational module depends on the other; engine,
testkit and workbench dependencies retain their existing structure. The root
and `testJVM`/`testNative` aliases include the bridge. The isolated paragraph
component additionally depends on `textUI.native`; native artifact linking and
the one-Rust-library rule are unchanged.

The provisional core text API now has explicit UTF-16 `TextPosition` plus
logical `TextAffinity`, optional `TextCaret`, `TextHit` with all alternatives,
and `TextSelectionRegion` with line/interpolation metadata. A caret call must
name its affinity; the old single-offset/rectangle result cannot express a
bidi or wrap boundary and has been replaced. Hits return the complete result
rather than reducing it to an Int. Selections return sorted visual regions
instead of discarding their metadata. Original text, logical size, ink bounds,
glyph/feature completeness and overflow are exposed on the same result.
Existing source consumers did not implement or call the replaced methods;
the authoring corpus was type-checked after this change.

`ResolvedTextLayout` retains the **identical** `ParagraphLayout` or
`WrappedParagraphLayout`. Carets, hits and selections delegate to its shared
geometry. UTF-8 offsets convert through the original source to UTF-16. Double
coordinates map 1:1 to `Lp`, with no display scaling, snapping or size changes.
All line indices, affinities, caret kinds and hit alternatives survive.
Its recording operation delegates to the retained paragraph with explicit
core-origin and ARGB-to-straight-sRGB conversion. Glyph run identities, resolved
faces, painter order and relative placements remain unchanged.

Invalid caret queries return None, including surrogate/grapheme interiors and
out-of-source/negative convenience offsets; `caretsAt` returns empty. Negative
`TextPosition` construction rejects. Invalid/reversed selections throw without
snapping, and nonfinite input/recording points reject. Nearest-stop ties keep
the shared downstream-then-source-order primary and every alternative. This
chooses a geometry contract, not visual navigation, strong/weak cursors or an
editing command policy. Zero-width line-height caret bars remain independent
of any host-painted caret thickness. See [the bridge contract](../../../text-ui/README.md).

## Actual `TextServices` path

The isolated paragraph component implements `NativeTextServices` with an
immutable explicit style map. Each `NativeTextStyle` supplies already-open
exact static font faces and existing paragraph options. Unknown styles reject;
no default family, implicit style/size fallback or OS lookup is inferred.
Finite nonnegative widths call the existing exact word wrapper; positive
infinity requests unwrapped layout through the same paragraph pipeline.
Negative/NaN widths, unsupported inputs and existing budget failures reject.
The service returns the pure adapter around that exact result.

The existing `Committed` call-site requirement is unchanged. The service stays
on its creating Scala thread. The caller owns and closes every supplied font
and Unicode service; the service opens/closes none and creates no worker or
callback. Closed services prevent later preparation; earlier immutable results
remain valid and can first build geometry/record after native closure.

No kernel transaction, identity, lifetime, command, scheduling or publication
semantics changed. These tests provide the public `Committed` marker at their
call sites. They exercise real native text data but do not establish mounted
phase dispatch or scheduling. The existing off-UI-owner slow-work policy still
applies; this service does not automatically make a synchronous call async.
It remains in the isolated probe rather than the production native host.
