## Implemented and reviewed

The finite-capacity scheduler separates transaction-owned reservations, publication,
explicit execution and explicit terminal delivery. Workers run under a UI ownership
guard. No worker executes during dispatch, staging or effect draining. There are no
threads or foreign callbacks in this adapter.

Scope.latest settles Pending/failure atomically with final candidate input. Work
factories/reservations run after structural stabilization, so source/Inputs diamonds
and final-equal intermediate states cannot launch or cancel obsolete work. Input
failure invalidates old generations; recovery requests fresh work. LatestOnly drops
obsolete outcomes. Progressive retains stale results while newer input stays pending
and cannot regress accepted generations. Capacity waiting resumes without polling.

Synchronous actions and asynchronous commands now execute their contracts: staged
argument/enablement checks, implicit refusal attempts, independent concurrency and
acceptance, per-command bounded serial queues, dispatch-time snapshots, explicit
cancellation and stable bounded status. withArg rechecks the staged argument. Failed
enablement disables/reports; same-command reentrant dispatch refuses.

Every invocation receives terminal data, even when acceptance suppresses application
reconciliation. Only accepted results update lastResult. Explicit cancellation
suppresses reconciliation; soft Supersede cancellation leaves acceptance to policy.
Noncooperative executing serial work retains its slot until actual termination and
delivery, preventing newer external writes from overtaking older saves. Queued
cancellation can terminate without executing. Bookkeeping commits before separate
owner-checked completion reconciliation, so handler refusal/defects cannot strand
resources or rerun work. Failed bookkeeping retains completed work for redelivery.

The snapshot-save regression saves revision 17 while revision 18 is current, marks
only 17 saved, and then runs the queued revision-18 save in order. SnapshotAssociated
returns captured S; the application's monotonic revision logic establishes its save
marker. The kernel does not inspect arbitrary snapshot types.

Independent source review found and re-reviewed fixes for intermediate-pass launch,
reentrant admission and unrequested interruption permitting reruns, plus clarified
synchronous current metadata. Review requested independent latest coverage, command
disposal scripts, final-equal structural controls and worker-outcome metadata; all
are present. Final source verdict found no remaining blocker, conditional on those
controls and final JVM/Native checks. Reviewer ran no builds or edits. Main session
ran verification. See `../design/decisions/2026-10-27-controlled-work.md`.

## Remaining gates

The controlled adapter is single-owner and has no synchronization/publication claim
for real workers. Real worker threads, bounded progress channels and foreign C
producers require separate transport, pressure, cancellation and retirement tests.
Deadlines/debounce, Events/settle diagnostics, frame parking, reparent/outlets,
virtualization, rendering/input and native/GPU retirement remain open. Full Stage 1
still needs its remaining laws, semantic review and authoring review against the
real API. This tranche does not close all of C1.6a's delivery requirements.

Scheduler capacity bounds job resources. Existing graph traversal/copying, retained
terminal application data and diagnostics are not process-memory/performance
qualification; the bounded diagnostic trace is still C1.8 work. Executing work runs
only when the headless driver explicitly requests it, and can block that driver.
Fatal VM errors remain outside ordinary Outcome failure handling. Cancellation
cannot undo external effects, and application completion is a separate transaction
from terminal bookkeeping. The pinned-upstream GC pause gate is unchanged and no
soak was launched. Next: bounded progress delivery and a real worker adapter.
