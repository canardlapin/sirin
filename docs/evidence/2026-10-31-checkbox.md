# Checkbox on the public seam, 2026-10-31

## Claim

`Checkbox(checked, label)(onChange)` and `Checkbox.bind(cell, label)` work.
Before this, both were `???` placeholders that the authoring corpus already
called. The checkbox is a public element, in
`core/src/main/scala/sirin/CheckboxElement.scala`, built like `Button`:
- the label is prepared text, measured at the offered width;
- activation is the standard element activation: pointer release, Space or
  Enter release, or an assistive Activate;
- the semantics are one `Role.Checkbox` node named by the label.

A toggle asks the owner for the opposite of the committed state, and the box
shows only what the owner commits. `bind` writes the cell.

`Semantics` gains `checked: Option[Boolean]`, defaulting to `None`. It is the
state of a checkbox or other toggle; `selected` remains the selection state.
Native accessibility transport still publishes only buttons and text inputs,
so `checked` reaches headless semantic snapshots but not VoiceOver yet.

## Checks and results

Run on macOS arm64 with JDK 25.0.4.1, from task branch `checkbox-20261031`.

- **`CheckboxSeamSuite` (desktop, real text and renderer): 2 new tests.**
  - A bound checkbox exposes `Role.Checkbox`, its label and `checked =
    Some(false)`.
  - A pointer click checks it. The repaint differs from the unchecked frame,
    and the label is not reshaped.
  - Space toggles on release, not on press. Keyboard focus adds a ring. An
    assistive Activate through the activation binding toggles it again.
  - A controlled checkbox whose owner does not write reports the request
    `true`, keeps showing unchecked, and paints identically. After the owner
    commits `true`, the next request is `false`.
- **Pictures.** `desktop/target/checkbox-seam/{unchecked,checked,focused}.png`
  show an outlined box and an accent box with a check mark, each beside the
  label.

Suite results: `testJVM` 439, `testNative` 439, `desktopJVM/test` 116,
`probeParagraph/test` 40, and `examples/compile` passed. The
`ValidatedForm`, `KeyedList` and `PopupFocus` corpus programs now compile
against a real checkbox. Their other placeholders remain.

## Limits

There is no mixed state, no native accessibility transport for checkboxes, and
no owner visual review of the box's design. Enter toggles as well as Space
because element activation treats them alike; a form that wants Enter to
submit must handle it before the checkbox does.
