# Events, deadlines and bounded driver, 2026-10-28

Base checkpoint: `606f45d`. Authorized tranche: transactional events, monotonic
quiet-period deadlines and a unified bounded owner driver with diagnostics.
Concurrent graphics/text/core-text bridge edits are preserved and excluded.

## Implemented

Scoped EventSource emits stage with their transaction. Publication snapshots live
subscriptions, preserving emission/registration order. Source/subscriber disposal
prunes queued delivery. Map/filter run read-only at delivery; each candidate gets
one transaction and one budget unit, even if filtered. Handler refusal/defect is
reported and consumed, leaving other recipients eligible. Handler-emitted events
append only after their successful publication. Staging and routed fanout have
finite host capacity; overflow refuses before state/lifetime/work publication.

KeyedCell.changes reports final committed revisions, not intermediate mutations.
Initialization/change-and-restore/refused transactions produce no batch. Removals,
insertions, moves and same-key replacements replay sequentially by index. A longest
retained subsequence minimizes moves among retained keys. Batch construction uses
full synchronous snapshots and vector edits; it is not a viewport/range algorithm
or an asymptotically optimized large-list diff. Filtered-source revision/delta
streams remain explicitly deferred under C1.6b.

Debounce initializes with the first settled value and then owns one replaceable
monotonic deadline. Equal/final-equal/rolled-back inputs do not postpone it;
returning to the displayed value cancels it. Success/failure values use the same
quiet-period semantics and input equality, including signed zero. Due ties use
registration order. Input publication before servicing a due timer supersedes it.
Disposal/provisional rollback clears pending metadata, including through a retained
binding. Failed delivery is reported/consumed once. Invalid intervals, backward
clocks and arithmetic overflow fail explicitly. ManualClock is synchronized/atomic
and can wake a parked host without running a UI callback or a timer thread.

HeadlessRuntime.drive rotates events, deadlines, progress, completions and effects
under one candidate-unit budget. Failed completion bookkeeping rotates to other
jobs and retries at most once per turn. A failed progress receiver stops progress
for that turn. Ready work remaining at a consumed budget reports exhaustion; this
is not proof of a cycle. awaitActivity parks on transport activity or the next
real-clock deadline; manual-clock advancement wakes it. Empty turns schedule no
active turn and append no driver trace. Legacy explicit drains/pump remain usable.

A configurable bounded ring records numeric cause/parent IDs, kind/outcome enums,
graph/structural pass counts and driver unit counts. Event/deadline/effect follow-ons
link to originating transactions. CycleDetected, transaction BudgetExceeded and
turn-budget exhaustion have distinct receipts/traces. The ring retains no signals,
scopes, payloads, exceptions or callbacks. It is not a complete graph inspector or
a new complete-working-state repetition detector. Dependency-cycle proof and
existing graph/structural budgets remain authoritative.

The independent source reviewer ran no edits/builds. Completion starvation,
retired deadline metadata, ceiling arithmetic and exact rollback-control findings
were fixed and re-reviewed. Final source verdict found no remaining bounded blocker;
see [review decision](../design/decisions/2026-10-28-events-deadlines-driver.md).
