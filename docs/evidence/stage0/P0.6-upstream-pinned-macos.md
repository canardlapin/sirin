## Stress protocol

All runs use `probes/gc-repro/run.py`, which records binary hashes, stdout,
stderr, exit/timeout status, elapsed wall time, GC environment, and host load.
Each process runs alone with respect to this investigation. The host is shared
and heavily loaded, so these runs cannot establish idle-host pause behavior.
No unrelated processes were stopped. Heap figures are logical GC capacity,
not live bytes or RSS. Existing assertions remain unchanged.

## Completed standalone controls

| Case | Settings | Outcome |
|---|---|---|
| `repro-w4-120` | 120 s, 4 workers, 2,048 slots each, 128 MiB cap | exit 0; **34.13 MiB at every sample from 5–120 s** |
| `repro-real-oom` | 10 s request, 4 workers, 16,384 slots each, 16 MiB cap | reports OOM then **SIGABRT** after 0.141 s; external timeout did not fire |

The successful run completes 539,201,235 iterations and 21,999 collections,
retaining 4,320,088 array-payload bytes. Stdout/stderr show no worker errors
or GC warnings. The matching stock trap-based baseline exhausted the same
128 MiB cap after 73.18 s; see `P0.6-standalone-macos.md` for that receipt.
These finite runs establish observed stability, not a universal growth bound.

The oversized control prints `java.lang.OutOfMemoryError: Scala Native heap
space`, then `Failed to throw exception, not found a valid catch handler for
exception when unwinding execution stack.` The watchdog records signal 6
(return code -6; runner status 134). It demonstrates prompt failure under
real exhaustion, **not graceful/recoverable OOM behavior**. No claim is made
that this abort has the same cause as the original growth race, or that
application-level OOM recovery is qualified.

## Ten-minute Sirin event soak

Command (same 128 MiB cap and 15 s GC sync timeout):

```sh
python3 probes/gc-repro/run.py \
  --out target/upstream-evaluation/sirin-w4-events-600 --timeout 620 -- \
  target/upstream-evaluation/bin/threads-fa4a9e6 soak 600 4 1000
```

**The process exits 1: two existing pause assertions fail.** It completes
600.0 s of work (602.095 s including startup/exit), without OOM, deadlock,
GC synchronization warnings, or external timeout.

| Measurement | Observed result |
|---|---:|
| GC heap capacity, every 60 s sample and final report | **34.1 MiB** |
| Completed allocation iterations | 2,859,523,605 |
| Collections | 118,257 |
| Mean recorded collection duration | 0.743 ms |
| Events pushed / received | **1,499,373 / 1,499,373** |
| Push failures | 0 |
| Event latency p50 / p99 / p99.9 | 0.18 / 3.98 / 23.59 ms |
| Maximum event latency | **166.983 ms — FAIL** |
| Maximum ticker oversleep | **152.124 ms — FAIL** |
| Ticker oversleeps above 50 ms | 96 |
| Final resident memory | 67.1 MiB |

The heap plateau persists through substantially longer execution than the
stock capped OOM reproduction. Event delivery and the no-deadlock checks
pass for this run. Mean GC duration is not the maximum pause, and these
measurements do not identify whether GC or host scheduling caused the tails.

One-minute system load was 16.12 at start and 14.84 at end on ten logical
CPUs. External process observations are retained alongside the run. The
host was not idle, so the failed latency checks must remain failures rather
than being excused or extrapolated to an idle machine.

## Conclusion and next gate

The complete pinned upstream toolchain builds successfully, passes Sirin's
31 existing tests, and suppresses the reproduced Immix growth failure in
both the standalone 120 s workload and the event-bearing 600 s Sirin probe.
It is a concrete evaluation candidate, with source and artifact provenance.

**P0.6 remains open.** The 50 ms criteria fail in the long run. Re-run this
same pinned binary on an idle host; if the long tail persists, correlate
pause timing with collection and thread scheduling before changing runtime
policy. The separate historical safepoint stall was not observed here,
but this does not prove that specific failure fixed. Commix and recoverable
OOM behavior are not qualified by this evaluation. No production pin or
kernel semantics changed, and no upstream message was posted.
