# P0.6 follow-up: standalone allocation OOM on macOS arm64

Date: 2026-10-27. **P0.6 remains blocked.**

## Finding

The heap-growth failure reproduces in a standalone Scala Native 0.5.12
program with no Sirin, SDL, wgpu, mailbox, or custom C implementation.
Four allocating workers exhaust a 128 MiB heap cap in both release-fast
safepoint modes. A one-worker control stays at 8.53 MiB for 40 seconds.
Removing the survivor ring does not remove the growth: four workers with
zero retained payload finish 30 seconds at 69.03 MiB.

This isolates a runtime/workload reproduction. It does **not** establish
which collector or allocator mechanism is responsible, prove a live-object
leak, or qualify any runtime workaround. Disabling trap-based yieldpoints
does not resolve this OOM. The separately reported safepoint stall was not
observed in this bounded set of runs and remains unresolved.

## Environment and controls

- Checkout base `1fc105e`; local investigation branch `investigate/gc-threading`.
- macOS 15.1.1 (24B91), arm64, 10 logical CPUs, 32 GiB RAM.
- Temurin JDK 21.0.12.1, Apple clang 16.0.0.
- Scala 3.7.4, Scala Native 0.5.12, sbt 1.12.14; release-fast, Immix,
  multithreading enabled, no LTO.
- All experiment processes ran serially. The host was shared, with recorded
  one-minute loads between 6.52 and 12.73. This is **not an idle-host rerun**
  and no performance or 50 ms pause qualification is claimed.
- Every run used `GC_MAXIMUM_HEAP_SIZE=128M` and an external Python timeout.
  Standalone runs also set `SCALANATIVE_GC_SYNC_TIMEOUT_MS=15000`.
  None of the seven experiment runs reached the external timeout.
- The two standalone binaries differ only in build-time
  `SCALANATIVE_GC_TRAP_BASED_YIELDPOINTS=0` for the conditional variant.
  A clean rebuild was used. `nm` confirms two trap symbols in the default
  binary and zero in the conditional binary.
- `otool -L` shows the standalone executables link only
  `/usr/lib/libSystem.B.dylib`. There are no vendor framework dependencies.

## Results

Heap values are the runtime's heap-capacity counter
(`scalanative_GC_get_used_heapsize` returns `heap->heapSize`), not live bytes
or RSS. Last samples before an OOM are **not** the exact terminal heap size.
The 128 MiB setting also budgets GC metadata, so it need not equal the
reported usable heap capacity. Wall times include process startup/exit.

| Case / receipt directory | Requested duration | Result | Heap observation |
|---|---:|---|---|
| `original-release-w1` | 40 s | exit 0, 41.04 s wall | 8.5 MiB final; no stall; ticker max oversleep 26.449 ms |
| `original-release-w4` | 60 s | **OOM**, exit 1 at 54.23 s | original probe fails before its 60 s sample |
| `repro-immix-trap-w1` | 40 s | exit 0, 40.17 s wall | 8.53 MiB at every sample from 5 s; 1,077,424 retained payload bytes |
| `repro-immix-trap-w4` | 60 s | exit 0, 60.55 s wall | 46.93 MiB at 5 s → 122.26 MiB at 60 s; 4,336,560 retained payload bytes |
| `repro-immix-trap-w4-long` | 90 s | **OOM**, exit 1 at 73.18 s | last sample: 124.76 MiB at 70 s |
| `repro-immix-conditional-w4` | 90 s | **OOM**, exit 1 at 60.22 s | last sample: 122.53 MiB at 55 s |
| `repro-immix-trap-w4-no-survivors` | 30 s | exit 0, 30.13 s wall | 24.00 MiB at 5 s → 69.03 MiB at 30 s; zero retained payload bytes |

All three OOM exits include `Out of heap space cannot allocate more objects`
and the small-object allocation path. The reduced program uses byte arrays,
short temporary lists, and temporary decimal strings. Worker-owned rings
remain observable and are checked after join; they cannot be removed as
unused stores. Even with 2048 slots per worker, the maximum four-worker
retained array payload is 8,511,488 bytes. The zero-slot run removes these
retained arrays entirely, while keeping the same allocation loop.

The original no-event control's zero event latency measures no delivered
work; it does not satisfy the event-latency criterion. The standalone program
does not measure UI latency or use the original native wait path.

## Reproduce

The independent build and its runner are in `probes/gc-repro/` and can be
copied outside Sirin. See its README for arguments and all build variants.

```sh
cd probes/gc-repro
sbt nativeLink
GC_MAXIMUM_HEAP_SIZE=128M SCALANATIVE_GC_SYNC_TIMEOUT_MS=15000 \
  python3 run.py --out target/immix-w4 --timeout 105 -- \
  target/scala-3.7.4/gc-repro 90 4 2048 true
```

Change worker count to `1` for the control. Change slots to `0` to remove
survivors. For the conditional variant, preserve logs/binaries outside this
nested build's `target` before running:

```sh
SCALANATIVE_GC_TRAP_BASED_YIELDPOINTS=0 sbt clean nativeLink
```

The runner preserves nonzero exits, sends SIGKILL to its own process group
at its deadline, and records whether the deadline fired. Smoke checks verified
success (exit 0), application failure (exit 7), and external timeout (exit 124).

## Upstream context and next work

Checked against the upstream tracker on 2026-10-27:

- [#5051](https://github.com/scala-native/scala-native/issues/5051), open,
  reports macOS release-mode safepoint stalls and motivates the conditional
  comparison. Similar symptoms do not establish identity with Sirin's stall.
- [#5046](https://github.com/scala-native/scala-native/issues/5046), closed,
  reports trap-path live-array corruption. This follow-up has not reproduced
  that specific corruption.
- [#5052](https://github.com/scala-native/scala-native/issues/5052), closed,
  reports Commix growth under repeated explicit collection. The reduced
  Immix program here never calls `System.gc()`, so that report does not
  explain this result by itself.

Next: instrument GC free-block and per-mutator recycled-block accounting to
separate allocator starvation/fragmentation from retained roots; compare
Commix and debug mode using this reduced workload. Repeat the original
single-worker native-wait case on an idle host and capture thread stacks if
the stall recurs. The 10-minute/50 ms gate remains open. This source bundle
is ready for review before deciding with the owner whether to file upstream;
no upstream issue or comment has been posted.
