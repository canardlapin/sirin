## P0.1: pointer-only shim and ABI check

**State: demonstrated on all three ABIs.**

| ABI | Where | Result |
|---|---|---|
| AArch64 | macOS 14, locally and on GitHub `macos-14` | 14/14 |
| SysV x64 | GitHub `ubuntu-latest`, SDL3 console build from the pinned tarball | 14/14 |
| Win64 | GitHub `windows-latest`, clang plus MSVC import libraries | 14/14 |

CI run [40532460783](https://github.com/canardlapin/sirin/actions/runs/40532460783)
ran at commit `b1d9a0fa4f2e3fb0a9db923d5c6db913417e36cc`. Every artifact
download was SHA-256 verified in the log. On Linux and Windows this proves
layouts and linking only. No window or GPU was exercised there.

**Binding method.** We hand-wrote externs, plus a C shim
(`sirin_shim.c`) that Scala Native compiles from `resources/scala-native/`.
The shim follows these rules:
- **By-value wrappers.** Every function that takes or returns a struct by
  value (`wgpuInstanceRequestAdapter`, `wgpuAdapterRequestDevice`,
  `wgpuSurfaceCapabilitiesFreeMembers`) has a pointer-only wrapper.
- **Callbacks.** The adapter, device, and uncaptured-error callbacks (which
  take `WGPUStringView` by value) are C trampolines. They write into
  caller-owned *native* memory and never call into Scala.
- **Waiting.** Requests use `WGPUCallbackMode_AllowProcessEvents`, and
  Scala drives `wgpuInstanceProcessEvents`. So no Scala code runs inside a
  wgpu callback.
- **SDL constants.** Event types, the `SDL_KeyboardEvent.key` offset,
  `SDLK_ESCAPE`, and `sizeof(SDL_Event)` are read from the headers through
  the shim, rather than transcribed into Scala.

`sbt probeWindow/test` gives 14 passed, 0 failed:
- 12 struct layouts match the C compiler's `sizeof`/`offsetof` exactly:
  - `WGPUChainedStruct`, `WGPUStringView`, `WGPUSurfaceSourceMetalLayer`,
  - `WGPUSurfaceDescriptor`, `WGPUSurfaceConfiguration`,
    `WGPUSurfaceTexture`,
  - `WGPUColor`, `WGPURenderPassColorAttachment`,
    `WGPURenderPassDescriptor`,
  - `WGPUSurfaceCapabilities`, `WGPURequestAdapterOptions`,
  - `sirin_request_result`.
- A `WGPUColor` passed by value through C round-trips intact, including
  `Double.MaxValue` and `Double.MinPositiveValue`.
- The SDL constants agree with known values (`SDL_EVENT_QUIT` = 0x100,
  `SDL_EVENT_KEY_DOWN` = 0x300, `sizeof(SDL_Event)` = 128).

**Finding: wgpu-native extension enum values.**
`wgpuSurfaceGetCurrentTexture` returned status `0x30001`. That is
`WGPUSurfaceGetCurrentTextureStatus_Occluded`, which is defined in
wgpu-native's `wgpu.h`, not in the standard `webgpu.h`. Two consequences:
- Bindings must include `wgpu.h` extension values, and engine code must not
  treat statuses outside the `webgpu.h` set as errors.
- *Occluded* means "the window is not visible: skip the frame and wait for
  expose". It is not a reason to reconfigure the surface. The first version
  of the probe reconfigured on every failure, which was wrong.

## P0.2: SDL3 window, wgpu clear, idle parking, resize, shutdown

**State: demonstrated on macOS.** P0.2b (live drag-resize) is separate and
not yet run.

| Criterion (roadmap) | Result |
|---|---|
| SDL3 window → Metal layer → wgpu surface; clear and present | ✅ Pixel size 1600×1040 at scale 2.0; surface format `0x1c` (`BGRA8UnormSrgb`) |
| DPI-scale query | ✅ `SDL_GetWindowDisplayScale` = 2.0 |
| 1,000 programmatic resize cycles with no crash | ✅ 10,000 cycles, exit 0 |
| RSS slope within ±1 MB over 10 × 1,000 cycles | ✅ after warm-up (see below) |
| 60 s idle: zero presents, no more than ~1 wake/s | ✅ 1 loop wakeup, 0 events, 0 presents. `top` shows 0.0% CPU and 0 idle wakeups over a 20 s sample. |
| Clean shutdown | ✅ All wgpu objects released, Metal view and window destroyed, `SDL_Quit`, exit 0 |

**RSS during the 10,000-cycle resize**, sampled every 1,000 cycles in-process
through `task_info(MACH_TASK_BASIC_INFO)`. The values are in MB:

```text
start 44.0 | 1k 53.2 | 2k 53.3 | 3k 53.4 | 4k 45.0 | 5k–10k 45.1
```

After the first 1,000 cycles, resident memory stays flat or falls; the drop
at 4k is consistent with the allocator returning pages. Across the last
7,000 cycles the slope is 0.0 MB per 1,000 cycles.

**Occluded frames.** During the resize run, 6,720 of 10,000 frames reported
*Occluded* and 3,280 presented. The probe was launched from a background
agent process, so the window may not be frontmost. Occlusion here is a
property of the environment, not a probe failure, but it does mean the
present path was exercised 3,280 times rather than 10,000. A rerun with the
window frontmost should be recorded when P0.2b runs by hand.

**Loop parking.** `SDL_WaitEventTimeout` is declared `@blocking`. The idle
loop waits for the whole remaining interval and does not tick. As a
consequence, the idle run had exactly one loop wakeup.

## Not covered here

- P0.2b, live drag-resize through the re-entrant paint path. This needs a
  human at the machine.
- P0.6 and P0.7: GC stress while blocked, and entry from foreign threads.
- CI on x64 Linux and Windows, which waits on S-0.4.
- Debug mode only. Release-mode numbers come with P0.9.

## How to reproduce

```sh
native/fetch-macos.sh
sbt probeWindow/test probeWindow/nativeLink
B=probes/window/target/scala-3.7.4/sirin-probe-window
$B resize 10000
$B idle 60 &  sleep 15; top -l 2 -s 20 -pid $! -stats pid,cpu,idlew
$B            # interactive; Escape or close to quit
```
