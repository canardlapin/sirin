# P0.6: Immix allocation-race diagnosis

Date: 2026-10-27. **Heap-growth mechanism identified; P0.6 remains open.**

## Finding

Scala Native 0.5.12 Immix can treat a lost collector-ownership race as a
completed collection. Under concurrent allocation this causes unnecessary
heap expansion and eventually false exhaustion. This mechanism is present
in the pinned source, observed in an instrumented standalone reproduction,
and suppressed by two independent, small runtime variants.

The standalone program has no Sirin/SDL/custom-C implementation. Sirin's
runtime pin and production build configuration remain unchanged. The private
patched JARs are diagnostic artifacts, not a qualified runtime distribution.

## Mechanism and evidence

In the pinned runtime:

1. `Synchronizer_acquire()` fails to acquire the collection mutex, calls
   `scalanative_GC_yield()`, and returns false.
2. Yield only waits when `Synchronizer_stopThreads` is set. Another collector
   can hold the mutex before requesting a safepoint, so the losing caller
   can return without any collection having occurred.
3. `Heap_Collect()` returns void on this path. `Allocator_allocSlow()` then
   treats another failed allocation as post-collection exhaustion and grows
   by one block, or exits at the heap cap.

The epoch diagnostic records **1,152 allocator misses with no completed
collection between entry and return**, all counted before the final printed
checkpoint. At each printed checkpoint `collected=0`, `epoch_delta=0`, and
`without_collection` equals the miss count. This is direct evidence of the
premature-return path; instrumentation alone does not locate the exact
instruction window within the collection mutex's lifetime.

The initial diagnostic run reaches the 128 MiB cap and exits after 58.85 s.
A late sweep reports 3,506 free blocks out of 3,787: over 92% fully free.
Thus reclamation succeeds while capacity repeatedly expands. Mid-allocation
`own_recycled` counts are stale in 0.5.12 because consuming the list does not
decrement that counter; `list_empty=1` in the second diagnostic prevents
mistaking those counts for proof of stranded usable blocks. This experiment
does not diagnose every possible source of Immix heap growth.

## Bounded controls

Same host/toolchain as `P0.6-standalone-macos.md`: macOS arm64, Scala 3.7.4,
Scala Native 0.5.12, release-fast, no LTO. Standalone variants use conditional
yieldpoints, linked after clean with `SCALANATIVE_GC_TRAP_BASED_YIELDPOINTS=0`.
Processes run serially under an external watchdog and a 15 s GC sync timeout.
The host is shared and heavily loaded; these are correctness experiments,
not throughput comparisons or idle-host latency qualification. Heap values
are runtime capacity, not live bytes or RSS.

| Case | Duration / cap | Outcome |
|---|---|---|
| Stock conditional Immix (earlier receipt) | 90 s / 128 MiB | OOM after 60.22 s |
| `diag-w4` | 90 s / 128 MiB | OOM after 58.85 s; mostly free after sweep |
| `diag-epoch-w4` | 20 s / 128 MiB | exit 0; 75.40 MiB final; premature collection returns observed |
| `retry-w4` | 120 s / 128 MiB | exit 0; 34.13 MiB at every sample from 5–120 s |
| `alloc-retry-w4` | 120 s / 128 MiB | exit 0; 34.13 MiB at every sample from 5–120 s |
| `alloc-retry-real-oom` | 10 s / 16 MiB | expected OOM, exit 1 after 0.048 s; no timeout |

Both successful candidates use four workers and 2,048 survivor slots each.
The narrower allocation-retry run completed 671,568,539 iterations and 26,845
collections; final retained array payload was 4,296,632 bytes. Its cap control
uses 16,384 slots per worker, a workload whose steady live set exceeds 16 MiB;
it fails in `Heap_Recycle` with `growIfNeeded:re-init cursors`. This confirms
that the patch does not suppress that real-exhaustion path. It does not prove
all allocation sizes, collectors, or recovery paths correct.

`--retry-collection` loops until the caller acquires collection ownership.
`--retry-allocation` instead changes the internal `Heap_Collect` return to a
boolean and makes the allocator retry when collection ownership was lost.
The latter avoids forcing an additional collection after every lost race.
Neither is a complete backport of upstream allocation recovery.

## Original Sirin probe

The original SDL threading probe was clean-linked in release-fast with the
same allocation-retry JAR using a temporary sbt classpath setting. Trap
safepoints remained enabled (two `yieldpoint_trap` symbols in `nm`).
Command: `soak 90 4 0`, cap 128 MiB, external timeout 105 s.

It completed 90.1 s of work without OOM or deadlock, with heap capacity
34.1 MiB at both its 60 s sample and final report (stock OOM: 54.23 s).
However, **the probe exited 1**: maximum ticker oversleep was **159.429 ms**,
so the existing 50 ms assertion failed. Host load was 28.75 at start and
30.74 at end on a 10-CPU machine. We cannot attribute this pause to either
GC or host contention from this run. No events were pushed; the printed
zero event latency is vacuous. This is supporting evidence for the growth
fix, explicitly **not a passing P0.6 or latency result**.

The clean link used this session-only setting (no root build-file change):

```sh
sbt -Dsirin.mode=release-fast \
  'set probeThreads / Compile / dependencyClasspath ~= { _.map(entry => if (entry.data.getName.startsWith("nativelib_native")) Attributed.blank(file("/absolute/path/runtime-alloc-retry.jar")) else entry) }' \
  probeThreads/clean probeThreads/nativeLink
```

## Upstream match and adoption path

Live upstream inspection found [PR #5128](https://github.com/scala-native/scala-native/pull/5128),
merged **2026-10-26**, commit `fa4a9e6ac9dab73ab4d476d6cc8c0cdc422c25f7`.
It addresses lost collection races and adds a broader recovery protocol:
collection generations, reservation while mutators are stopped, reuse of
other allocators' available space, and corrected block accounting.
This is a direct source/mechanism match, not a claim that upstream's full
implementation was built or tested in this checkout.

The [latest published release](https://github.com/scala-native/scala-native/releases/tag/v0.5.12)
was still **0.5.12** when checked on 2026-10-27. Consequently a version bump
to an already published stable release cannot yet supply this fix.
The preferred next experiment is a reproducibly pinned upstream build
containing #5128, followed by Sirin's full qualification matrix. The small
local patch is useful causal evidence, not a substitute for that evaluation.
No upstream issue/comment was posted; a duplicate growth report is unnecessary.

The separate macOS safepoint stall remains unresolved locally. Upstream
[#5051](https://github.com/scala-native/scala-native/issues/5051) is still open;
symptom similarity does not establish identity. No claim is made for Commix.
P0.6 still requires the 10-minute, event-bearing, below-50-ms pause gate on
an idle host, plus a deliberate runtime-policy decision.

## Reproduction and preserved artifacts

`probes/gc-repro/README.md` describes the independent build and opt-in runtime
JAR substitution. `runtime/variant.py` patches exact source anchors into new
private JARs; the shared Coursier cache remains untouched. The nested default
build still selects the published 0.5.12 runtime.

`gc-allocator-race-20261027/` contains raw stdout/stderr and watchdog records,
exact generated C patches, source/output JAR hashes, build logs, upstream
status metadata, and a manifest. The earlier baseline receipts remain in
`gc-repro-20261027/`. Executables and private JARs are kept locally under
`target/gc-investigation/`, not checked into source control.

## Repository validation

After the experiments, `sbt testJVM testNative` passed against the unchanged
published runtime: two JVM and two Native core tests, with no failures.
Engine/testkit currently have no test cases in those aliases. Python scripts
parse successfully; `git diff --check` passes. The earlier full checkout
validation covers ABI/mailbox tests (31 total); those were not rerun here.

## Complete upstream evaluation follow-up

[P0.6-upstream-pinned-macos.md](P0.6-upstream-pinned-macos.md) records the full
build at #5128's merge commit: all 31 tests pass; standalone 120 s and original
600 s event soak hold the heap at 34.1 MiB. The long soak receives every event
but fails both 50 ms assertions on the shared host. This supersedes the
pending upstream-build experiment above; runtime adoption remains open.
