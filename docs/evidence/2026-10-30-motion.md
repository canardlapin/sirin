# Motion, 2026-10-30

## Claim

`scope.animate` works. Animations belong to their scope and run on the runtime's
monotonic clock. A new target continues from the current value and velocity.
Content that is not on screen settles instead of animating and schedules no
frames. Under reduced motion every change reaches its target in the next frame.
Ticks never write application state or run a transaction. `View.offset` moves
drawing, hit testing and semantics together. The design is in
[the decision](../design/decisions/2026-10-30-motion.md).

## Checks and results

Run on macOS arm64 with JDK 25.0.4.1 and the pinned Scala and Scala Native
toolchain, from task branch `motion-20261030`. Every check uses `ManualClock`,
so timing is deterministic.

- **`MotionSuite` (engine, JVM and Native): 7 tests.**
  - Curve continuity: a retarget mid-flight keeps the value and velocity, and the
    new segment ends at its target after one duration.
  - Easings: `Linear`, `Decelerate` and `Standard` hit their expected midpoints.
  - Frames: frame waits round up to 17 ms at 60 Hz. The transaction count does
    not change while frames advance.
  - Hidden content: an animation that the latest frame did not sample settles,
    whether at retarget or when it is next sampled.
  - Reduced motion: no frames, and turning it on settles motion in flight.
  - Lifetimes: disposing the scope, or refusing the construction, leaves no
    animation behind.
  - Elements: presentation is sampled per frame without new revisions. An
    unchanged sample keeps the same frame.
- **`MotionPresentationSuite` (desktop, real text and renderer): 3 tests.** These
  run the A-0b `ReducedMotion` program.
  - At 80 ms of a 160 ms transition, the moving button's semantic bounds are
    offset by exactly 90 of 180 logical units, and its size is unchanged.
    Opacity is 0.75.
  - At 160 ms it reaches 180, and no opacity group remains. A click at the old
    position does nothing; a click at the new position runs the command.
  - Under reduced motion, the target position appears in the next frame with
    no animation wait.
  - Unmounting the content stops its frames.
- **`DiagramSeamSuite` drag lift: 1 new test.** During a node drag, pixels change
  at 45 ms and again at 90 ms. Semantic parts, shaped-text counts and
  transaction counts stay fixed. After release, pixels return to the
  pre-lift frame exactly. Panning schedules no lift frames.

Suite results:

- Full `sbt testJVM`: 429 passed (422 before, plus 7).
- Full `sbt testNative`: 429 passed.
- `desktopJVM/test`: 113 passed (109 before, plus 4).
- `examples/compile` passed.

## Changes in observable behavior

- The development theme no longer reports reduced motion. It said so before,
  but nothing animated.
- An opacity below 1 now paints its view as an isolated group, and an offset now
  moves its view. Both decorations used to fail capture as deferred.
- The diagram editor shows a shadow under selected nodes while a node drag is
  active.

## Limits

No native window was run, so motion has not been reviewed visually at real
frame rates. The macOS reduced-motion preference is not read. Frame waits assume
a 60 Hz interval rather than the display's own rate. Real-window frame pacing
and latency under motion are unmeasured.
