# Retained GPU host tranche — 2026-10-28

Candidate: `codex/retained-gpu-host-20261028`, based on responsive host
`f4acc6c`, with the newer bounded batch renderer and stroke compaction overlaid.
The host's PixelProgram/reference extensions and kernel files are preserved.

The window replaces its bootstrap surface with one on the batch instance,
owns that batch device, and lends a reference to its Scala-created
render worker. The worker owns compilation, geometry/mask/image caches and tile
preparation. Completed tiles export immutable texture references; presentation
samples them directly on that same device. A complete frame owns its references
until replacement/retirement, independently of tile-cache eviction. No routine
RGBA readback or upload is admitted. Explicit capture remains a readback.

Tile outputs and variants remain bounded: 256 entries and 1,048,576 output
pixels per cache, 256 tiles per frame, and at most three outstanding exported
frames. A tile's temporary batch program obeys the existing 640x360, 16-program,
192MiB payload bounds; it retires after exporting its output. Changed tiles upload in queue order and at most four programs
submit together before completion/export; standalone Native probe calls retain
their synchronous behavior. Existing batch
atlas/mesh limits and all graphics precision and pixel budgets remain fixed.
Whole-frame unchanged requests bypass layout, preparation, compilation, upload
and dispatch. Changed pixel-affecting commands invalidate their tiles. Scale,
resize and generation changes invalidate target-dependent variants. Overlay
commands share tile compilation with base commands to preserve painter order
and linear-light composition. No GPU blending of already resolved transparent
tiles is used to approximate drawing semantics.

Acceptance: independent reference pixel comparisons at scales 1, 1.25, 1.5, 2;
unchanged-frame counters; changed/reverted tiles; cancellation and stale-result
retirement; resize and disposal; required JVM/Native aliases and desktop tests.
Record source hashes and all failed receipts. Frozen host workload and gates
stay unchanged: action p95 <=50ms/p99 <=100ms; scroll <=100/200ms; 20 warmups
and 100 measured inputs per class, 600x360 logical/1200x720 physical, 100 rows.
One final quiet attempt uses the existing 85% idle/half-core load preflight.
A refusal remains not_run; diagnostic runs cannot qualify responsiveness.

Out of scope: kernel semantics, full graphics capability qualification,
unbounded path preparation, editing/IME/accessibility and backend adoption.
