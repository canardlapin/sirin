# Sirin roadmap and Stage 0–1 plan

Date: 2026-10-27, revised the same day after two reviews: a fresh-context review (round 2) and an external design review (round 3).
Design authority: `docs/design/VISION.md`.

Stages are gated by demonstrated capabilities, not dates. Stage 0 (native
feasibility) and Stage 1 (executable core) run in parallel after the S-0
skeleton is in place.

## Preconditions

  source builds of native dependencies. Homebrew `sdl3` tried to compile

  `bbuchsbaum`, so the remote needs repo-local account routing (the

  representative.
- **Toolchain.** Scala 3.7.4, sbt 1.12.14, Scala Native 0.5.12,
  sbt-scala-native-crossproject 1.3.2, and munit with ScalaCheck.

**Graphics track (owner direction, 2026-10-27).** The public graphics API has a
browser-level capability, visual-quality, and authoring target (VISION §7.1).
The [graphics API plan](2026-10-27-graphics-api.md) defines the capability matrix
and qualification work for general `sirin-graphics`: standalone drawing,
reusable recording, and backend-specific preparation. Controls, diagrams/editors,
text, images, animation and dense scenes define the corpus. Direct wgpu lowering
remains the baseline; a bounded ThorVG comparison and backend decision complete
by the Stage 2 graphics exit. Skia is a conditional alternative. API authoring,
recording and reference fixtures can proceed during Stage 1; renderer integration
follows existing native gates. Intaglio portability/adapter work proceeds as a
separate downstream track and does not define or block the general nucleus.
Stage 2's nucleus is the first slice, not completion of this requirement.

The standalone `graphics` JVM/Native module now implements vector/image
recording, owned image snapshots and bounded resource inspection, with no UI or
native dependency. Its contract, tests and
limits are linked from the graphics plan's implementation checkpoint. It does
not complete G-0/G-1, establish a renderer, or qualify the Stage 2 nucleus.

The separate `textNative` component now shapes explicit static font runs and
produces owned grayscale glyph masks with pinned HarfBuzz/FreeType and font
fixtures. This advances part of P0.3b; the GPU atlas/goldens, complete shared text
layout and fallback remain open. See the graphics plan's text-component evidence.

The isolated `probeUnicode` now exercises ICU4X segmentation and raw bidi
analysis through pointer-only boundaries, with pinned Unicode reference data.
The generated C API's older grapheme/line algorithms required the bounded
upstream-algorithm adapter documented in VISION §6.1. See the
[P0.8 component receipt](../evidence/graphics/2026-10-27-unicode.md). Full P0.8
acceptance, trimmed locale data, matched ICU4C comparison and production combined
host integration remain open.

The next Unicode component adds `BidiLine`: upstream L1/L2 results with exact
source codepoint maps and actual paragraph base levels. The complete pinned
BidiCharacterTest corpus is exercised separately from the existing raw-level
prefix tests. [The line receipt](../evidence/graphics/2026-10-27-bidi-lines.md)
records this bounded coverage. That component alone did not supply shaping/
L3/L4, fallback, paragraph placement or shared UI editing geometry.

`probeParagraph` now integrates the real Unicode and font components for
grapheme-aligned script itemization, explicit supplied-face fallback and
unwrapped paragraph placement. One immutable result supplies measurement and
exact glyph recording, with source-global mappings and explicit missing text.
See [the paragraph receipt](../evidence/graphics/2026-10-27-paragraph.md).
That checkpoint did not qualify OS font discovery, wrapping, shared editing
geometry, the core adapter, production hosting or GPU glyph acceptance.

Word wrapping now uses the same line kernel and immutable `TextLineLayout` as
unwrapped layout. Exact candidate reshaping, per-line bidi, preserved script
context, Unicode/grapheme-safe opportunities, shared budgets and explicit
unbreakable overflow are exercised by real-font tests. See
[the wrapping receipt](../evidence/graphics/2026-10-27-wrapping.md).

Shared editing geometry now reads these stored lines/runs: grapheme-only stops,
logical affinity for bidi/wrap edges, nearest-stop hits with alternatives, and
possibly discontiguous selection regions. Font GDEF ligature interiors are used
where usable; other interiors explicitly interpolate actual cluster advances.
See [the geometry receipt](../evidence/graphics/2026-10-27-editing-geometry.md).
The pure `text-ui` bridge now connects those results to core `TextLayout` with
explicit UTF-16 affinity, all hit alternatives, line/quality metadata and 1:1
logical-unit conversion. The isolated paragraph component supplies actual
`TextServices` through an explicit style/font map; finite widths wrap and
positive infinity requests unwrapped layout. Exact glyph recording retains
the same result. See [the adapter receipt](../evidence/graphics/2026-10-28-text-ui.md).
The current core Canvas interface now records through pure `graphics-ui`:
public vector operations/scopes and resolved text, with lexical/thread guards
and rollback. Explicit `PreparedText` inventory preparation precedes paint;
paint-time text services are immutable lookup and missing requests reject.
The real-font public Element specimen shares measurement/selection/drawing
results. Rounded rectangle paths use explicit cubic corners, without claiming
pixel/renderer qualification. See [the Canvas receipt](../evidence/graphics/2026-10-28-canvas-ui.md).
Editing/navigation/IME, mounted phase/worker dispatch, hard-line/tab/hyphenation
policies, OS discovery, production host/GPU and broader visual qualification
remain open.

The [bounded offscreen slice](../evidence/graphics/2026-10-28-offscreen.md) now
adds executable target-bound CPU preparation and actual wgpu pixels for paths,
images, positioned static-font masks, path clips and isolated opacity at all
four scales. A pinned ThorVG shared-device probe works for the admitted seam,
but its tested color composition fails the linear-light contract. It is not
adopted. Strokes/gradients, the full fixture/performance corpus, production GPU
resources/atlases, mounted host and G-2 backend decision remain open. This
reference interpreter does not replace the production CPU-tessellation baseline.

## Stage 0: Native feasibility (macOS by hand; Windows and Linux in CI only)

Each probe is a small Native app in `probes/` and gets an evidence note in
`docs/evidence/stage0/`. Probes are sized to about one agent session each.

| # | Probe | Pass criterion |
|---|---|---|
| P0.1 | **Shim + ABI.** A hand-written pointer-only C shim for the wgpu calls that P0.2 needs: adapter and device requests, plus a `WGPUStringView` callback trampoline. `userdata` is passed as a handle index. The shim exports `sizeof` and `offsetof`, and the probe builds the matching Scala `CStruct` layouts. | The ABI test passes locally, and later in CI on AArch64, SysV, and Win64. A by-value round trip works through the shim. The binding method is recorded. |
| P0.2 | **Window + clear.** SDL3 window, Metal layer, wgpu surface, clear and present, an idle `SDL_WaitEvent` loop, programmatic resize, a DPI-scale query, and clean shutdown. | 1,000 programmatic resize cycles with no crash. A 60 s idle window makes **zero presents** and wakes no more than about 1 time/s (`top -stats idlew`). The RSS slope over 10 cycles of 1,000 is within ±1 MB. |
| P0.2b | **Live resize.** Drag-resize the window by hand while it repaints through the re-entrant path, using an event watch or SDL main callbacks. | Content follows the drag with no stretched frames. Frame times are logged, and the chosen mechanism is recorded. |
| P0.3a | **SDF rounded-rect quad** at 1x, 1.5x, and 2x scale | Golden tests pass at ≤1/255 per channel on the Metal adapter, with separate goldens per adapter |
| P0.3b | **Glyph run.** Text shaped by HarfBuzz and rasterized by FreeType into an atlas with subpixel-positioned bins, using a font file pinned in the repo | Golden tests pass within the documented tolerance. Pen positions stay fractional, with only the baseline snapped. The sRGB/linear and gamma choices are recorded. |
| P0.3c | **Copy path.** Upload a managed `Array[Float]` through a borrowed pointer and through a native copy, measuring bytes at each hop: application storage, marshalling, staging, GPU resource. | A table of copies and ownership rules for each hop goes into the evidence note. |
| P0.4 | **IME (macOS).** SDL3 composition for Japanese kana-kanji and Chinese pinyin, with the candidate window placed at the caret | A scripted list of 10 sequences is all correct. Gaps in surrounding text and reconversion are recorded, along with the scope of an `NSTextInputClient` adapter if one is needed. *Windows TSF: blocked.* |
| P0.5a | **AccessKit attach (macOS).** Button and text field exposed; VoiceOver reads them and activates the button. | VoiceOver announces the controls and can activate them. The callback-thread map is documented. |
| P0.5b | **AccessKit in CI (Windows and Linux).** Hidden-window attach (`SDL_WINDOW_HIDDEN`, required before the window is shown), a UIA tree walk through PowerShell, and an AT-SPI tree dump on Linux. | The tree is exposed with roles and names. This proves exposure, not screen-reader quality. Narrator: blocked. |
| P0.6 | **Threads, GC, re-entry.** Workers allocate under stress while the main thread sits in `@blocking SDL_WaitEvent`. wgpu callbacks fire inside `@blocking WaitAny`. | 10 minutes with no deadlock. The longest pause is below 50 ms. The re-entry behavior is documented. The cost of strict extern semantics is measured as a fallback. |
| P0.7 | **Foreign-thread entry — HARD GATE.** Threads that Scala Native did not create (host pthreads, plus AccessKit's and SDL's own threads) call the shim, which copies an owned message into a native mailbox and calls `SDL_PushEvent`. Cases: concurrent callbacks during a GC; callbacks during shutdown; unregistering while a callback is in flight; callback re-entry from inside a native call. | 10⁶ deliveries per case with no crash or leak. The shim asserts that no Scala frame ever runs on a foreign thread. Shutdown and unregister races are clean under TSan. **Stage 1 integration of the native host does not start until this passes on the pinned 0.5.12 runtime.** |
| P0.8 | **Unicode.** ICU4X C FFI for grapheme, word, and line segmentation and bidi levels, called through the shim; pinned upstream algorithms missing from the generated C API may use the bounded adapter in VISION §6.1 | API checklist complete. Binary and data size recorded with compiled data. The cost of a trimmed-data custom build is recorded. |
| P0.9 | **Iteration cost.** A generated program of about 100k lines shaped like UI code (reachable code, closures, generic composition), with Scala Native incremental compilation, in debug and release-fast modes. Body, public-API, and dependency edits are timed separately; warm and clean builds are reported separately. | Numbers recorded. If a warm edit-to-window cycle exceeds 20 s (an escalation threshold, not a target), open the JVM/Panama dev-host decision. That host would require behavioral parity tests. |
| P0.10 | **Software-GPU CI.** P0.3a runs headless through WARP and lavapipe | The golden test passes in CI, against goldens specific to each adapter |
| P0.11 | **Packaging (macOS).** An `.app` bundle, an `@executable_path` rpath, ad-hoc codesign with the hardened runtime, and a notarization dry run | The bundle launches from `/Applications` with no Homebrew or vendor paths |

**Order.** Start with P0.1 and P0.2. P0.6 and P0.7 then establish the thread
model, and the remaining probes are largely independent.

**Exit.** Every probe ends in exactly one of four states:

| State | Meaning |
|---|---|
| **demonstrated** | It works through the intended stack. |
| **demonstrated with adapter** | It works, and the adapter is implemented and exercised by the probe. |
| **deferred and unsupported** | It is explicitly out of the supported matrix for now, and the docs say so. |
| **blocked** | It cannot be tested yet, for example for lack of Windows hardware. |

A proposed adapter that has not been built counts as *blocked*, not as
*demonstrated*. Stage 0 exits when P0.1, P0.2, P0.6, and P0.7 are
demonstrated, every other probe has a state, and no foundational probe is
blocked on macOS. Development can continue on provisional platforms, but
the evidence note must say exactly what has been established.

**Kill and pivot triggers.** Each one leads to a decision with the owner,
not a workaround.

- The shim plus ABI tests cannot keep the wgpu bindings stable (P0.1, P0.6).
  Pivot to Dawn.
- SDL3 IME and accessibility attachment both fail (P0.4, P0.5). Pivot to
  our own small per-OS C/ObjC shell.
- Foreign-thread marshalling or blocking re-entry proves unsound (P0.6,
  P0.7). Escalate to the Scala Native maintainers.
- Link time is unworkable and the Panama host is rejected (P0.9). Revisit
  the premise.

## Stage 1: Executable core (headless, JVM + Native)

The semantics are specified in VISION §5.1–5.4, including the accepted
R1–R16 amendments and independent review corrections. The first static C1.2a/b
slice and integer reference comparison passed on JVM/Native. Dynamic flatMap,
transactional scope lifetimes and static mount identity are now implemented, with
expanded independent dynamic-expression/lifetime oracles and bounded review; see
`docs/evidence/c1-topology-20261027.md`. Live Inputs and keyed headless
ForEach/Switch are now implemented with an independent reconciliation oracle; see
`docs/evidence/c1-reconciliation-20261027.md`. Explicit reparent/outlets, rendering
and full Stage 1 exit remain open. Controlled tasks and commands now have independent
policy/latest models and bounded review; see `docs/evidence/c1-work-20261027.md`.
Bounded progress and real workers are now qualified, followed by scoped events,
keyed batches, monotonic debounce and a unified bounded driver; see
`docs/evidence/c1-events-20261028.md`. The target is to test all laws with ScalaCheck against testkit's controlled
scheduler. A run-counting harness checks how many times things run. The
reference evaluator is independent and compares **ordered observations,
effect counts, command outcomes, and live ownership and resource sets**,
not only final values.

| # | Task | Laws / verification |
|---|---|---|
| C1.1 | Opaque ids and units, (slot, generation) handles, the error ADT, and the handle table that also backs C `userdata` | A stale handle always fails with a typed error |
| C1.2a | `Signal`, `Cell`, `UiTxn`: stage, evaluate the candidate snapshot, publish atomically, notify | Glitch-freedom. At most one evaluation per derivation per committed pass (run counting). No observer sees new sources with old derived values. Root refusal discards every write; scoped attempt refusal rolls back only its staging. Defects crossing runtime-owned boundaries poison the transaction despite a catch. A write inside a derivation is an error. |
| C1.2b | Speculative derived reads in a transaction; `Failed` values; `txn.require` | `{x.set(2); y==4; x.set(3); y==6}`. A throwing derivation publishes `Failed` atomically while the cell writes stand. `require` refuses the innermost attempt or the root transaction. |
| C1.2c | **Headless flatMap complete**: private between-pass attachment, cycle/budget failure, rollback and unreachable graph retirement. Headless component Switch is implemented in the bounded C1.5b slice. | Fixed topology within a pass. New nodes are evaluated in the next pass. Observers see only settled states. |
| C1.3 | **Headless scoped events, keyed committed batches and debounce complete**; independent virtual-time oracle plus bounded unified driving and explicit cycle/budget diagnostics. Filtered streams now follow C1.6b below; full Stage 1 remains open. | A cycle requires a dependency cycle or a complete deterministic working-state repeat. Exceeding the budget is never reported as a cycle. Observers never see an unsettled state. |
| C1.4 | Independent static/dynamic expression, scoped lifecycle and keyed reconciliation evaluators implemented. Controlled command/latest scheduling oracles now cover policy combinations and completion order. The independent slot-history oracle and targeted JVM/Native threaded tests now qualify the bounded headless transport; foreign C producers remain open. | Randomized programs give identical ordered observations, effect counts, and ownership sets under both evaluators |
| C1.5a | **Headless lifecycle complete**: transactional scopes, cells/watches/effects, static owner/position/definition mount, generation-checked callbacks, lease release. Component rendering and native retirement remain separate. | Disposal stops all publications. A stale callback has no effect. |
| C1.5b | **Headless Inputs/ForEach/Switch complete**, including synchronous O(n) keyed cells and rollback. **Headless retained reparent/outlets complete** with runtime-global keys, duplicate/cycle/rollback and owner-disposal controls; interactive placement remains open | **Same key with a new value updates displayed inputs and keeps local draft state, through value replacement and reordering.** Duplicate keys fail. An implicit owner change resets state. `reparent` preserves state. |
| C1.6a | **Controlled and real-worker headless scheduling plus bounded progress complete**. Scala-created fixed pool, transactional reservations, close/cancel/wakeup and retirement have an independent oracle and threaded tests; public-API workbench runs on JVM/Native. Foreign C producers and desktop integration remain open. Contracts: lifetime validity, independent Concurrency/Acceptance policies, current/stale completion metadata, committed snapshot association, and delivery policies | A disposed owner is never written. The save-r17-during-r18 law holds. Independent invocations do not invalidate each other. The latest-only liveness law holds under randomized latency. |
| C1.6b | **Headless synchronous filtered revisions/batches, tagged range windows and fixed-height virtualization complete** with independent interval/revision/lifetime oracle. Scroll-only changes avoid full projection scans; source/query updates rebuild the projection and retain synchronous diff costs. Remote paging, variable heights and interactive layout remain open | Realized count is at most visible plus overscan. No full scans. Replacement, insertion before the viewport, deleting the selection, reordering, and stale ranges are all handled. |
| C1.7 | **Headless command execution complete**: synchronous actions, argument bindings, enablement/validation, transactional dispatch, concurrency/acceptance and terminal retirement. Desktop binding qualification remains separate. | A command disabled during dispatch is refused. Its outcome follows its policy. |
| C1.8 | **Headless numeric cause/parent traces and bounded ring implemented**; transaction pass counts and driver exhaustion are recorded. Full invalidation tagging/inspector remains open. | Every unit has a cause. Ring memory is bounded. A trace never retains a disposed component. |
| C1.9 | **Bounded headless driver/counters and activity/deadline parking implemented**. Empty turns schedule no active turn; rendered frames, animation and idle power remain unqualified. | With no invalidations, animations, or deadlines, zero frames are scheduled. A caret-style deadline schedules exactly its own frames. |
| C1.10 | Lessons register with the four GPUI cases. Tests that need paint, focus, or selection are **visibly pending**, skipped with a reason and their target stage, never passing stubs. | The pending count appears in the test report |

**Exit** requires all three:
1. All laws pass on JVM and Native.
2. A fresh-context review signs off on the semantics.
3. A review of the **authoring corpus (A-0)**, recompiled against the real
   API, finds it clean.

Passing laws alone does not approve the API.

## Working method

- **Ownership.** The main session owns kernel semantics (C1.2–C1.7) and the
  public API.
- **Agents.** Agents take the native probes after P0.1 has fixed the shim
  pattern.
- **Every change carries:** its invariant, tests, platform notes, and
  evidence.
- **Review.** A fresh-context review happens before each stage exit.
