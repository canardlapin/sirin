# Bounded JVM host source review, 2026-10-28

Scope: JDK25 FFM macOS development shell, immutable committed tree capture,
minimum full layout, shared text/recording integration and bounded reference GPU
presentation. The VISION host contract was updated before the kernel boundary
changes. Controls, IME, accessibility and shipping remain separate.

The existing independent reviewer inspected source without editing or building.
Six findings were addressed: runtime-relative timer waits; cleanup spanning all
acquisitions and worker retirement; alignment against actual allocated cross
extents; accepting/presenting unchanged empty feedback; consecutive feedback
budget reset after successful presentation; and a DPI-aware physical framebuffer
limit. Later review covered tiling, request ownership counters, eight partial-open
faults, runtime wake-listener clearing and scenario completion guards. No remaining
bounded source blocker was found. Main-session validation then completed on the
frozen source: both required platform suites, examples, desktop tests and native
main-thread scenarios all exited zero. See the
[receipt](../../evidence/jvm-host-20261028/README.md).

The decision does not qualify request timeout/late-callback delivery: the native
fault stages run after successful adapter/device requests. Detachment prevents
future wake registration delivery, but already captured callbacks may finish;
window wake/close are serialized. OS screenshot/visual acceptance remains open
because the desktop connector could not bind the unbundled Java process. Native
surface receipts and renderer captures do not replace that gate. The combined
source hashes include separately owned, uncommitted graphics work; this is not a
standalone clean-checkout release decision.
