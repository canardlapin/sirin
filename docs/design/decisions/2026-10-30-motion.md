# Motion

VISION §8.2 specifies motion, and the design review (D5) requires it before the
API freeze. This note records how it is built. `Scope.animate` now returns a
working `Presentation[Double]` instead of refusing with `Deferred("animation")`.
No transaction, identity, lifetime, scheduling or command-policy semantics
change.

## Curve and retargeting

Each animation is one cubic Hermite segment over the runtime's monotonic clock,
in `engine/src/main/scala/sirin/engine/MotionRuntime.scala`. A segment starting
from rest takes its slopes from the easing: `Standard` eases in and out,
`Decelerate` starts fast, `Linear` is linear. A retarget while moving starts a
new segment from the current value and the current velocity, so motion never
snaps or queues. The segment always ends exactly at its target and the
transition's duration. Momentum can carry a value past its target before it
returns, so hosts clamp opacity to the range 0 to 1.

## Ticks, retargets and frames

Animation values are samples of the curve at a frame's time. A tick is
therefore a read, not a write. It runs no transaction and touches no cell or
signal, and a `Presentation` still cannot enter signal composition.

The target is an ordinary `Signal[Double]`. The animation watches it, so a
retarget arrives after the commit that changed it, like any other committed
observer. The animation's starting value is the target's value when the
animation is created. Animations belong to the scope that created them: they
end when it is disposed, and a refused construction leaves none behind.

`HeadlessRuntime.present(body)` marks one presented frame. Hosts capture every
window inside it. Every animation sampled in `body` sees the same clock time and
counts as on screen. The desktop host wraps each application capture in
`present`.

- **Hidden content.** An animation that the latest frame did not sample is not on
  screen, whether because its content is hidden, unrealized or unmounted. A
  retarget then settles it at the new target. One that misses a frame settles
  when it is next sampled. Neither schedules frames.
- **Frame scheduling.** `animationWaitMillis` is -1 unless an animation sampled
  in the latest frame is still moving. In that case it is the time left until
  the next frame interval, which defaults to 1/60 s. The desktop event loop
  waits for whichever comes first, the animation frame or the kernel's
  existing deadlines.

This adds a wake source to the host loop, as VISION §8.2 asks. It does not change
how or when driver work, deadlines or transactions run.

## Reduced motion

`HeadlessRuntime.reducedMotion` is the platform preference. While it is on,
every retarget settles immediately, so the next frame shows the target with no
frame train and no application write. Turning it on also settles any animation
in flight. The desktop host takes the value from its theme. The macOS
accessibility preference is not read yet, so the development theme's value is
off. It used to be on, but nothing animated then.

*(2026-10-31)* The application host now reads the macOS Reduce Motion setting
through the native shim (`NSWorkspace.accessibilityDisplayShouldReduceMotion`).
It reads it at startup and on every loop turn, and sets both the runtime and
the development theme. A change made while the host is parked applies after
its next wake. Evidence:
[docs/evidence/2026-10-31-reduced-motion.md](../../evidence/2026-10-31-reduced-motion.md).

## Coherent geometry

- **Offset.** `View.offset` is captured as a presentation hint holding the value
  sampled for that frame. Layout ignores it. Placement then moves the whole
  subtree, so paint, hit testing, semantic bounds and clipping all
  use the presented position in the same frame.
- **Opacity.** `View.opacity` paints its children as one isolated group, and only
  while it is below 1. An opacity group does not clip its children, so an
  offset inside one is clipped only by the views around both. Offset and opacity
  at rest add no node to the captured tree.
- **Elements.** An element's presentation input stays paint-only. Capture
  resamples it through `ElementFrame.presented`, which returns the same frame
  while the sample is unchanged. Model revisions, layout identity, hit testing
  and semantics are untouched, and so are render-cache keys for frames that did
  not change.
- **Layouts.** A `Layout.presented` frame resamples its state through
  `LayoutFrame.presented`, and layout pays for each changed sample, as VISION
  §8.2 requires.

## Proof

- `MotionSuite`, on the JVM and Native, covers the curve laws, ticks on the
  manual clock, hidden content, reduced motion, scope ownership and per-frame
  element sampling.
- The A-0b program `ReducedMotion.scala` runs as `MotionPresentationSuite` on
  the desktop host. The moving button's drawing, hit target and semantic bounds
  are checked against each other at the presented positions. It is clickable
  where it appears and not where it was.
- The public diagram (`specimens/workbench/.../demo/diagram`) has a paint-only
  drag lift. `DiagramSeamSuite` checks that pixels animate while geometry, text
  shaping and transaction counts stay fixed, and that panning does not lift.
